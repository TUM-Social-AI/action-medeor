# GPT Luna offer extraction evaluation — 2 October 2026

The final two-pass evaluation met the initial quality target. The configured Azure
`gpt-6-luna` deployment achieved **99.5% and 99.7% populated-field accuracy** against
source-reviewed expectations for five workbooks and eight synthetic quotation PDFs.
The corpus contains 180 workbook offer entries and 16 PDF items. There were no API/read failures.

| Measure | Pass 1 | Pass 2 |
|---|---:|---:|
| Offer precision | 100% | 100% |
| Offer recall | 195/196 (99.5%) | 196/196 (100%) |
| Populated-field accuracy | 99.5% | 99.7% |
| Missing-value accuracy | 99.3% | 100% |
| Quoted price text / currency / basis | 28/28 each | 28/28 each |
| Non-conflicting original price amount | 27/27 | 27/27 |
| Populated offer dates | 123/124 | 123/124 |
| Explicit offer-validity dates | 8/8 | 8/8 |
| Synthetic critical checks | All pass | All pass |

The conflict case retained the disagreeing text/numeric price evidence and no selected amount.
Prices per 100, per 4, per 42 and per 200 retain their original amounts and denominators; no
unit-price arithmetic is performed. Medication expiry and requested shelf life were not used
as offer-validity dates. Relative validity was preserved verbatim without date arithmetic.

Remaining differences matter for review: one partial offer was omitted in the first pass;
both passes left a date blank in a malformed mail-status note; and the second pass changed
duplicated quotation-mark characters in one product description. That last change also receives
an unverified-evidence warning. Eleven of thirteen documents had identical scored values across
passes. Missing-value scoring counts missing offers as incorrect fields, so the first pass's
null accuracy reflects the omitted record rather than invented dates/prices.

These results support further experimentation with Luna. They cover a small, partly sparse
corpus that informed prompt refinement; they are not an independent holdout or production
readiness claim. The earliest runs exposed wrong requested-versus-offered descriptions,
unstable source IDs and a contradictory synthetic footer. Those findings and earlier scores
remain in their reports. The final fixture revision has a neutral synthetic marker and
consistent totals; original workbook hashes were unchanged throughout.

Detailed final results are generated under `reports/luna-v3/report.md` and
`reports/luna-v3/results.json`, including all field differences, source excerpts, timings,
deployment/prompt/label versions and source hashes. Those reports and the data are Git-ignored.
Wrapped PDF descriptions are verified against both page text and extracted table cells.

Verification: **72 offline and existing parser/LLM regression tests passed**, Ruff passed,
and all eight PDFs regenerated byte-for-byte. No SharePoint calls, scheduled-job changes or
database writes were made. The creation-timestamp fallback remains future integration work.
